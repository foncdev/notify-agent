# 맥 알림을 안경·폰으로 받기 — 설정 가이드

맥에 뜨는 알림(카카오톡, 메일, 슬랙 등)을 Relay 알림 목록·안경 팝업·폰 앱으로 받는 방법이다.
처음 한 번 설정하면 그 뒤로는 맥이 켜져 있는 동안 저절로 돈다.

---

## 1. 어떻게 동작하나

```
맥 앱(카카오톡·메일…)
   │  알림
   ▼
맥 알림 센터 ──(알림 기록 파일)──▶ notify-agent ──(알림 훅)──▶ relay-service
                                   5초마다 읽음                     │
                                                                 ▼
                                                   Relay 폰 앱 · 안경 팝업 · 알림 목록
```

- **notify-agent**는 맥 알림 센터의 기록을 읽어, 고른 앱의 알림만 relay-service로 넘긴다.
- relay-service에 들어간 알림은 Relay 알림 목록에 쌓이고, 안경에 팝업으로 뜬다.
  **안경에서 Relay 플러그인이 켜져 있어도 보인다.** (시스템 알림은 플러그인이 켜져 있으면 가려진다.)
- 맥에 알림이 **뜨지 않으면** 넘길 것도 없다. 그래서 맥 쪽 알림 설정이 가장 중요하다(4장).

### 왜 이렇게 하나

| 방법 | 되나 | 이유 |
|---|---|---|
| 아이폰 Relay 앱이 다른 앱 알림 읽기 | 안 됨 | iOS가 앱끼리 알림을 읽지 못하게 막는다 |
| Even 앱의 기본 알림(안경) | 부분적 | Relay 플러그인이 켜져 있으면 가려진다 |
| **맥 알림 → notify-agent → relay-service** | 됨 | 맥이 켜져 있어야 한다 |

## 2. 처음 설정 (한 번만)

### 2-1. 설치

```sh
cd notify-agent
make install
```

- `~/.local/bin/notify-agent`에 설치하고, 로그인할 때마다 켜지게 등록한다(LaunchAgent).
- 설정 파일 `~/.config/notify-agent/env`를 만들고, 그 안에 **훅 키**를 새로 만들어 적는다.
- 설치 직후에는 권한이 없어 10초마다 다시 시도한다. 아래 2-2를 하면 저절로 읽기 시작한다.

### 2-2. 전체 디스크 접근 권한 주기

알림 기록은 macOS가 보호하는 곳에 있어 권한이 있어야 읽힌다.

1. **시스템 설정** › **개인정보 보호 및 보안** › **전체 디스크 접근**을 연다.
2. 목록 아래 **`+`** 를 누른다(암호·Touch ID를 물으면 입력).
3. 파일 고르는 창에서 **`⌘⇧G`** 를 누르고 `~/.local/bin/notify-agent` 를 입력해 **열기**.
4. 목록에 생긴 **notify-agent** 를 켠다.

> **터미널에서 직접 실행하면 권한 오류가 난다.** macOS는 권한을 notify-agent가 아니라 그것을 연
> 터미널 앱(iTerm·터미널) 기준으로 본다. 뒤에서 도는 notify-agent는 제대로 읽으므로 걱정하지
> 않아도 된다. 터미널 앱에 전체 디스크 접근을 주지 않는 것이 안전하다.

> **notify-agent를 다시 설치(`make install`)하면** 파일이 바뀌어 권한을 다시 켜야 할 수 있다.
> 로그에 권한 오류가 다시 보이면 목록에서 notify-agent를 껐다 켜거나, 지우고 다시 추가한다.

### 2-3. relay-service에 훅 키 넣기

notify-agent는 relay-service의 **알림 훅**(`/hooks/notify/mac`)으로 보낸다. 훅 키는 알림 추가만 할 수
있는 키라, 세션·파일·셸을 여는 마스터 키와 다르다.

1. `~/.config/notify-agent/env` 의 `NOTIFY_HOOK_KEY=` 뒤 값을 복사한다.
   - `.config`는 숨김 폴더다. `open -e ~/.config/notify-agent/env` 로 열거나 Finder에서 `⌘⇧G`.
2. `relay-service/.env` 에 한 줄을 넣는다.
   ```
   RELAY_HOOK_KEY=복사한값
   ```
3. relay-service를 다시 켠다. (`npm run dev`로 돌리고 있으면 끄고 다시 켜거나, 소스 파일 하나를 저장하면
   다시 읽는다.)

### 2-4. 가져올 앱 고르기

**비워 두면 아무것도 보내지 않는다.** 개인 메시지가 서버에 쌓이므로 사람이 골라야 한다.

1. 가져오고 싶은 앱의 알림을 맥에서 **한 번 받는다**(기록에 있어야 번들 id가 보인다).
2. 알림을 보낸 앱 목록을 본다. 터미널에서 그냥 돌리면 권한 오류가 나므로 launchd를 거쳐 돌린다.
   ```sh
   launchctl submit -l notify-apps -o /tmp/notify-apps.txt -e /tmp/notify-apps.txt -- ~/.local/bin/notify-agent apps
   sleep 3; launchctl remove notify-apps; cat /tmp/notify-apps.txt
   ```
   ```
   알림 수  번들 id  (앱 이름)
         12  com.kakao.KakaoTalkMac  (KakaoTalk)
          5  com.apple.mail  (Mail)
   ```
3. `~/.config/notify-agent/env` 의 `NOTIFY_APPS` 에 쉼표로 적는다.
   ```
   NOTIFY_APPS=com.kakao.KakaoTalkMac,com.apple.mail
   ```
4. notify-agent를 다시 켠다.
   ```sh
   launchctl kickstart -k gui/$(id -u)/com.foncsoft.notify-agent
   ```

### 2-5. 확인

```sh
~/.local/bin/notify-agent test                 # 시험 알림 하나(권한 없이도 된다)
tail -f ~/Library/Logs/notify-agent.log        # 동작 기록
```

- `보냈습니다` → 폰·안경 알림 목록에 `[notify-agent] 시험 알림` 이 보이면 relay-service까지 된 것이다.
  (`RELAY_LANG=en`이면 `Sent.` 와 `[notify-agent] Test notification` 이다.)
- 로그에 `notify-agent … 시작: … 앱 com.kakao.KakaoTalkMac,…` 가 있고 그 뒤로 오류가 없으면 정상이다.
- 이제 고른 앱의 알림이 맥에 뜨면 **5초 안에** `[앱 이름] 제목` 으로 들어온다.

## 3. 자주 쓰는 앱의 번들 id

`NOTIFY_APPS` 에 적는 값이다. 설치된 판에 따라 다를 수 있으니 **2-4의 목록으로 확인**하는 것이 정확하다.

| 앱 | 번들 id |
|---|---|
| 카카오톡 | `com.kakao.KakaoTalkMac` |
| 메일(Apple) | `com.apple.mail` |
| 캘린더 | `com.apple.iCal` |
| 미리 알림 | `com.apple.reminders` |
| 메시지 | `com.apple.MobileSMS` |
| 슬랙 | `com.tinyspeck.slackmacgap` |
| 텔레그램 | `ru.keepcoder.Telegram` |
| 디스코드 | `com.hnc.Discord` |
| Microsoft Outlook | `com.microsoft.Outlook` |
| Microsoft Teams | `com.microsoft.teams2` |
| 크롬(웹 알림) | `com.google.Chrome` |
| 사파리(웹 알림) | `com.apple.Safari` |

- `NOTIFY_APPS=*` 는 **모든 앱**이다. 시스템 알림(스크립트 편집기, 디스크, 스크린 타임…)까지 섞여
  알림이 금방 쌓이고 안경 팝업이 잦아지므로 권하지 않는다.
- 자기 번들 id를 모르는 앱은: `osascript -e 'id of app "앱 이름"'`

## 4. 맥 알림 설정 (가장 중요)

**맥에 알림이 떠야 넘어간다.** 알림이 안 오면 먼저 맥 화면 오른쪽 위에 알림 배너가 뜨는지 본다.

### 4-1. macOS 공통 — 시스템 설정 › 알림 › (앱)

| 항목 | 권장 | 설명 |
|---|---|---|
| 알림 허용 | **켬** | 꺼져 있으면 기록에 남지 않는다 |
| 알림 스타일 | **배너** 또는 **알림** | '없음'이면 기록에 남지 않을 수 있다 |
| 알림 센터에 표시 | **켬** | 알림 센터에서 빠지면 기록에서도 빠질 수 있다 |
| 미리보기 표시 | **항상** | '안 함'이면 내용 없이 들어올 수 있다 |

같은 화면 맨 위의 **미리보기 표시**(전체 앱 공통)도 **항상**으로 둔다.

### 4-2. 집중 모드

**시스템 설정 › 집중 모드** 에서 켜진 모드(방해 금지, 수면, 업무…)가 그 앱의 알림을 막고 있지 않은지 본다.
막힌 알림은 조용히 들어오거나 아예 뜨지 않는다. 필요하면 해당 모드의 **허용된 앱**에 추가한다.

### 4-3. 카카오톡(맥)

1. 카카오톡 › **설정** › **알림**
   - **알림 켜기**: 켬
   - **메시지 미리보기**(내용 표시): 켬 — 끄면 "새 메시지가 있습니다"처럼 내용 없이 온다
2. 채팅방별 알림: 알림을 끈 채팅방(종 모양에 사선)은 알림이 오지 않는다.
3. 참고: 카카오톡 맥 버전을 켜 두면 **폰의 카카오톡 알림이 꺼지는 설정**이 있다
   (설정 › 알림의 'PC 버전 사용 시 모바일 알림…'). 맥으로 받으면 폰 알림이 없어도 되지만,
   폰으로도 받고 싶으면 그 항목을 끈다.

### 4-4. 메일(Apple Mail)

1. 메일 › **설정** › **일반** › **새로운 메시지 알림**
   - **받은 편지함만** 또는 원하는 편지함. **VIP** 로 돼 있으면 VIP가 보낸 메일만 알린다.
2. 메일 › 설정 › **일반** › **새로운 메시지 확인**: **자동**(푸시) 또는 짧은 간격.
3. 메일 앱이 **켜져 있어야** 새 메일을 받아 알린다(로그인 항목에 넣어 두면 편하다).
4. 계정이 여럿이면 메일 › 설정 › **계정**에서 그 계정이 **켜져** 있는지 본다.

### 4-5. 슬랙

1. 슬랙 › **환경설정** › **알림**
   - 알림 대상: **모든 새 메시지** 또는 **다이렉트 메시지·멘션**
   - **알림 전달 방식**: macOS 기본 알림(시스템 알림)을 쓰게 둔다.
2. 슬랙 자체의 **알림 일시 중지**(방해 금지 시간)를 확인한다.

### 4-6. 캘린더·미리 알림

- 캘린더 › 설정 › **알림**: 각 계정의 **이벤트 알림**을 켠다.
- 일정의 **알림 시간**(예: 10분 전)이 정해져 있어야 그때 알림이 뜬다.

### 4-7. 웹 알림(크롬·사파리)

- 웹 사이트(지메일, 노션 등)의 알림은 브라우저 이름으로 온다(`com.google.Chrome` 등).
- 브라우저의 사이트 권한에서 해당 사이트의 **알림 허용**을 켠다.
- 브라우저가 **켜져 있어야** 알림이 온다.

### 4-8. 아이폰 알림을 맥으로 (선택, 확인 전)

macOS 15 이후 **아이폰 미러링**을 켜 두면 아이폰 앱 알림이 맥에도 뜬다.
이 알림도 맥 알림 기록에 남는다면 notify-agent가 넘길 수 있다. **아직 확인하지 않았다.**
켜 본 뒤 2-4의 목록에 아이폰 앱이 보이면 그 번들 id를 `NOTIFY_APPS`에 넣어 본다.

## 5. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| 로그: `알림 기록을 읽을 수 없습니다` | 전체 디스크 접근이 없다 | 2-2. 이미 줬다면 껐다 켜기, 재설치 뒤라면 다시 추가 |
| 터미널에서 `notify-agent`·`apps` 실행 시 권한 오류 | 터미널 앱 기준으로 권한을 본다 | 정상이다. 목록은 2-4의 launchctl 방식으로 본다 |
| 로그: `NOTIFY_APPS가 비어 있어…` | 앱을 고르지 않았다 | 2-4 |
| `test`: `503 … hook_disabled` | relay-service에 훅 키가 없다 | 2-3, 그리고 relay-service 다시 켜기 |
| `test`: `401 … 훅 키가 맞지 않습니다` | 두 키가 다르다 | `NOTIFY_HOOK_KEY` 와 `RELAY_HOOK_KEY` 를 같게 |
| `test`: `relay-service에 보내지 못했습니다` | relay-service가 꺼져 있거나 주소가 다르다 | relay-service 켜기, `NOTIFY_RELAY_URL` 확인 |
| `test`는 되는데 앱 알림이 안 온다 | 맥에 그 앱 알림이 안 뜬다 | 4장. 맥에 배너가 뜨는지 먼저 본다 |
| 맥에는 뜨는데 안 온다 | `NOTIFY_APPS` 에 그 앱이 없다 / 번들 id가 다르다 | 2-4 목록으로 번들 id 확인 |
| 로그: `알림 기록의 모양이 예상과 다릅니다` | macOS 업데이트로 기록 형식이 바뀌었다 | notify-agent를 고쳐야 한다(개발자에게 알리기) |
| 내용 없이 제목만 온다 | 미리보기가 꺼져 있다 | 4-1 미리보기 **항상**, 앱 자체의 미리보기 켜기 |
| 같은 알림이 두 번 온다 | (정상이라면 없다) | 로그를 확인해 알리기 |

로그 보기:

```sh
tail -50 ~/Library/Logs/notify-agent.log
```

같은 오류는 반복해서 적지 않는다(처음 한 번만). 오류가 없으면 시작 줄만 보인다.

`RELAY_LANG=en`이면 표의 오류 글이 영어로 나온다(예: `Can't read the notification history…`,
`Couldn't send to relay-service`, `Unexpected notification history format`). 로그의 시작 줄과
`NOTIFY_APPS가 비어 있어…` 안내는 언어와 상관없이 한국어다.

## 6. 명령 모음

```sh
# 다시 켜기(설정을 바꾼 뒤)
launchctl kickstart -k gui/$(id -u)/com.foncsoft.notify-agent

# 멈추기 / 다시 등록
launchctl bootout gui/$(id -u)/com.foncsoft.notify-agent
launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.foncsoft.notify-agent.plist

# 상태
launchctl print gui/$(id -u)/com.foncsoft.notify-agent | grep -E 'state|pid|last exit'

# 시험 알림
~/.local/bin/notify-agent test

# 설정 파일 열기
open -e ~/.config/notify-agent/env

# 지우기(설정·로그는 남긴다)
cd notify-agent && make uninstall
```

## 7. 설정 파일 전체

`~/.config/notify-agent/env` (권한 600)

| 이름 | 기본 | 뜻 |
|---|---|---|
| `NOTIFY_RELAY_URL` | `http://127.0.0.1:4100` | relay-service 주소 |
| `NOTIFY_HOOK_KEY` | 설치 때 만듦 | relay-service의 `RELAY_HOOK_KEY` 와 같은 값 |
| `NOTIFY_APPS` | (없음) | 가져올 앱 번들 id, 쉼표로. `*` 는 전부 |
| `NOTIFY_POLL` | `5s` | 알림 기록을 들여다보는 간격(1초 이상) |
| `NOTIFY_STATE` | `~/Library/Application Support/notify-agent/state.json` | 어디까지 보냈는지 |
| `NOTIFY_DB` | macOS 기본 자리 | 알림 기록 파일 |
| `RELAY_LANG` | `ko` | 글 언어(`ko`·`en`). relay-service의 `RELAY_LANG`, 폰 앱의 언어와 같게 둔다. 설치 뒤 만든 설정 파일에는 없으니 필요하면 한 줄 넣는다 |

바꾼 뒤에는 6장의 **다시 켜기**를 한다.

## 8. 알아 둘 것

- **맥이 켜져 있어야 한다.** 잠자기 중에는 알림도, 넘기기도 멈춘다.
- **처음 켤 때 지난 알림은 넘기지 않는다.** 켠 뒤에 온 것부터 넘긴다.
- **꺼져 있던 사이 온 알림은 다시 켜면 넘긴다.** 어디까지 보냈는지 적어 두기 때문이다.
  같은 알림을 두 번 보내지는 않는다.
- **relay-service가 꺼져 있으면** 넘기지 못한 알림에서 멈췄다가, 켜지면 거기서부터 보낸다.
- **개인정보**: 넘긴 알림(보낸 사람, 내용)은 relay-service에 저장되고 폰·안경에 보인다.
  꼭 필요한 앱만 `NOTIFY_APPS` 에 넣는다.
- **macOS 업데이트**: 알림 기록은 애플이 공개하지 않은 형식이라 업데이트 뒤 멈출 수 있다.
  로그에 `모양이 예상과 다릅니다` 가 보이면 알린다.
- 확인한 환경: macOS 26.5.2.
